## Intuition

Picking a polynomial order by whichever value drives training error lowest always answers
"the largest one available," because a bigger model can only match or beat a smaller one
on the data it was fit to. That is not a choice, it is a tie won by default.

A real choice needs a score the model could not have gamed by memorising. The cheapest
version holds out part of the data and never lets fitting see it. The catch is a genuine
trade: data spent watching is data not spent training, and a small watch set is a noisy
judge. Rotating which slice gets held out fixes the noise at the cost of fitting the model
several times over instead of once. A purely training-side score avoids that cost but has
to guess at the penalty instead of measuring it.

## The math

Cross-validation partitions the data into $S$ groups, trains on $S-1$ of them, and scores
on the remainder, rotated so every point is scored exactly once.

</Figure>

<Figure caption="What each scheme trains on versus checks, and how many times it has to fit." width="wide">

An entirely different route needs no held-out data at all. The Akaike information
criterion scores a model by its best-fit log likelihood minus a flat penalty per parameter:

<MathBlock id="1.73" name="Akaike information criterion">

$$\ln p(D \mid \mathbf{w}_{\mathrm{ML}}) - M$$

</MathBlock>

Larger is better. The penalty is fixed rather than measured from the data, which is why it
tends to favour models simpler than cross-validation would pick.

## Worked example

Twenty points, the same sinusoidal source as 1.1, model orders $M=0$ to $9$. Five-fold
cross-validation, using only training data, picks $M=5$. A held-out set of 100 points,
never touched during fitting, puts the true minimum at $M=5$ too: cross-validation reached
the right answer with a fifth of the data 1.1 used to reveal it in the first place.

<Figure caption="Left: the true answer, which needs 100 points nothing else here uses. Right: AIC, which needs none." width="wide">
  <AicPicksModel client:visible />
</Figure>

AIC, reading only the 20 training points and their fit quality, lands on $M=3$: close, but
one order simpler, exactly the "favours simplicity" tendency the penalty's fixed size
predicts.

## Recall

<Recall question="Why can't training error alone select model complexity?" concepts={["validation-set"]}>
Training error is the quantity being minimised, so a larger model can never score worse on
it than a smaller one it contains. It has no mechanism for penalising complexity.
</Recall>

<Recall question="What does cross-validation buy over a single hold-out split, and what does it cost?" concepts={["cross-validation"]}>
It uses every point for validation exactly once, instead of trusting one arbitrary split,
at the cost of S separate model fits instead of one.
</Recall>

<Recall question="Why does AIC tend to favour simpler models than cross-validation does?" concepts={["akaike-information-criterion"]}>
Its penalty is a fixed count of parameters, not a measurement of how much those parameters
actually overfit this data, so it cannot adapt the penalty the way held-out performance
does.
</Recall>

<Recall question="When is leave-one-out cross-validation the natural choice?" concepts={["cross-validation"]}>
When data is too scarce to spare a validation block of any real size; S=N uses all but one
point for training on every run.
</Recall>
