## Intuition

This chapter has been a good deal for one page of algebra. Fix some nonlinear functions,
stay linear in the weights, and you get closed-form fitting, a closed-form posterior, error
bars, and model selection without held-out data.

The reason not to stop here is in the first line of the deal. The functions are fixed before
the data arrives. In one dimension that is a mild inconvenience. In ten it is fatal.

The problem is coverage. Local bumps work by having one near wherever you want to predict.
Tiling a line takes a handful. Tiling a square takes that squared. Tiling a ten-dimensional
cube takes it to the tenth power. And you must lay them out before seeing the data, so you
cannot put them where the data is.

Two properties of real data rescue this. Data clusters near a lower-dimensional surface, and
targets depend on only a few directions along it. Both are useless to a fixed basis, because
exploiting either needs knowing where the data went.

## The math

No new equations here; the point is a counting argument about the ones already established.

Take Gaussian bumps of width $s$ in $D$ dimensions, wanting one within $s$ of any point in
the unit cube. Along one axis that needs about $1/s$. Covering the cube multiplies over
axes, so $M \sim (1/s)^D$. With $s = 0.2$ and $D = 10$ that is about ten million.

<Figure caption="Shrink the spacing and watch the count on the line, then on the square, then against dimension. The multiplication is what gets raised to the power of D." width="wide">

</Figure>

Every result in this chapter still holds at that size and none is any use. $\mathbf{S}_N$
from 3.54 is $M \times M$ and its Cholesky costs $O(M^3)$. The mathematics does not break;
the arithmetic becomes impossible.

<Figure caption="Polynomials are not an escape. Both counts explode with dimension, only at different rates, and a degree-3 basis is past any practical limit well before D reaches ten." width="wide">
  <BasisCountExplosion client:visible />
</Figure>

Note what $\gamma$ from 3.91 would say. It cannot exceed the number of observations, because
$\boldsymbol{\Phi}^{\mathrm{T}}\boldsymbol{\Phi}$ has at most $N$ non-zero eigenvalues. In
practice it settles well below even that, because packed basis functions overlap and
duplicate each other's coverage.

<Figure caption="Nominal count rises without limit; the effective count flattens far below it, and below N as well. Redundant basis functions add parameters the data never pays for." width="wide">
  <EffectiveVersusNominal client:visible />
</Figure>

The evidence framework diagnoses the problem exactly, and offers no way out, because the
basis was already chosen.

## Worked example

Handwritten digit images: 28 by 28 greyscale, so $D = 784$. Even two basis functions per
axis gives $2^{784}$, a number with 236 digits, against perhaps $10^{80}$ atoms in the
observable universe.

Yet the problem is tractable, because digit images do not fill that space. They lie near a
surface of maybe ten or twenty intrinsic dimensions, parameterised by stroke thickness,
slant and loop size. Almost every point in the cube is noise, not a digit.

<Figure caption="Toggle between spreading centres over the ambient square and placing them along the data. Almost every uniformly placed centre sits where no data ever appears." width="wide">
  <ManifoldInAmbientSpace client:visible />
</Figure>

So what is needed is not $2^{784}$ functions but enough to cover that manifold, sitting *on*
it, which you cannot arrange before seeing the data.

## Recall

<Recall question="Why does the number of fixed basis functions grow exponentially with input dimension?" concepts={["curse-of-dimensionality", "basis-function"]}>
Covering needs about $1/s$ functions along each axis, and over $D$ axes those counts
multiply, giving $M \sim (1/s)^D$.
</Recall>

<Recall question="What two properties of real data make the problem tractable?" concepts={["data-manifold"]}>
Inputs are correlated, so data lies near a manifold of far lower intrinsic dimension; and
targets depend on only a few directions within it.
</Recall>

<Recall question="Why can a fixed basis not exploit either?" concepts={["basis-function", "data-manifold"]}>
Both need to know where the data lies, and the basis is chosen before it is seen. Exploiting
them means placing functions at the data, or learning them.
</Recall>

<Recall question="What does γ report for a hugely over-specified basis?" concepts={["curse-of-dimensionality"]}>
Far below $M$, and below $N$ too, since overlapping basis functions duplicate coverage. The
framework diagnoses the waste without being able to fix it.
</Recall>
